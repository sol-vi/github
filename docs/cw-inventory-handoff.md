## 1. 役割とゴール

あなたは CW の社内業務ダッシュボードを設計・実装するUI/UXデザイナー兼フロントエンド設計者です。
在庫ダッシュボードは、SCM担当が**在庫金額・在庫日数（過剰／要補充）・賞味期限・滞留**を見て、
補充や在庫圧縮の判断を素早く行うためのページです。

構成は Google Spreadsheet（データ）→ Google Apps Script（取得・整形）→ HTML/CSS/JS（表示）。
受注売上ページと同じ GAS Web アプリ内の2ページ目（`?page=inventory`）として実装済みです。

## 4. アーキテクチャ

```text
RAW_Inventory（WMS在庫明細・1行=1ロット）
RAW_B2B（受注明細）── SKU で突合 ──┐
        ↓                          │
Code.gs  getInventoryData()  ←─────┘
  ├ ロットを正規化（数値・日付・カテゴリ判定）
  ├ buildDemandBySku_()：SKUごとの出庫数・購入価格・日次平均出庫
  └ payload = { meta, options, demand, rows（ロット） }
        ↓ google.script.run.getDashboardData({page:'inventory'})
InventoryScripts.html
  ├ enrich()：在庫金額・残日数・滞留日数をロットに付与（今日基準）
  ├ productRows()：ロット → SKU に集約、在庫日数・ステータス判定
  └ render()：KPI / チャート3種 / シグナル / 商品別表 / ロット別表
```

- ページ切替は `Code.gs` の `PAGE_TEMPLATES`（`b2b` → `Index`、`inventory` → `Inventory`）。
- `Inventory.html` は `<?!= include('Styles'); ?>` と `<?!= include('InventoryScripts'); ?>` を読む。
  **GAS上のファイル名は `InventoryScripts` で作ること**（違うと読み込めない）。
- プレビュー版では `window.__CW_PREVIEW_DATA__` に payload を注入し、GASを呼ばずに描画する。
  `InventoryScripts.html` はこの変数があればそちらを使う。

## 5. データソース

### 5-1. `RAW_Inventory`（必須）

WMS の在庫明細エクスポート。**1行 = 1ロット**。実データは 127行 / 40商品 / 1拠点（ソネッティーク）。

| 列名 | 使い方 |
|---|---|
| `商品コード` | **受注との突合キー**（JAN または自社コード） |
| `商品名` | 倉庫側の表記。画面表示は受注側の名前を優先 |
| `拠点名` / `在庫区分名` / `仕入先名` | フィルター軸（実データは拠点1・在庫区分は全て「通常品」・仕入先は空） |
| `在庫数` / `引当数` / `未引当数` | 総在庫 / 出荷待ち確保 / **有効在庫** |
| `ロットNo` / `入荷日` / `賞味期限` | ロット明細・期限管理 |
| `最終入庫日` | データ鮮度の判定 |
| `最終出庫日` | 滞留日数の起点 |

注意：

- **元ファイルは Shift-JIS（CP932）**。リポジトリの `data/RAW_Inventory_sample.csv` は UTF-8 に変換済み。
  Spreadsheet に取り込むときも文字化けに注意する。
- `カテゴリー名`・`数量単位`・`製造日` は**全行空欄**。カテゴリは商品名の `【…】` から判定している。
- `賞味期限` が入っているのは **27/127 ロットだけ**（酒類本体のみ。資材・ノベルティには無い）。

### 5-2. `RAW_B2B`（在庫ページでも使う）

在庫データには単価も出庫実績も無いため、受注データから取る。在庫ページで使う列は以下だけ。

| 列名 | 使い方 |
|---|---|
| `SKU（在庫保管単位）` | 突合キー |
| `購入価格` | 在庫金額の単価 |
| `発注数` | 出庫ペースの元 |
| `日付` | 出庫ペースの期間（日数）の算出 |
| `ステータス` | `確定済み`・`完了` のみ対象（`Config` で変更可） |
| `商品名` | 画面表示用の商品名 |

`getInventoryData()` は `RAW_B2B` を**任意扱い**で読む。シートが無いと全SKUが未突合になり、
在庫金額・在庫日数が全て「—」になる（エラーにはならない）。

## 7. 指標の定義

| 指標 | 定義 |
|---|---|
| 在庫金額 | `在庫数 × 購入価格`（原価ベース）。単価が突合した商品のみ |
| 有効在庫 | `未引当数` |
| 日次平均出庫 | 受注データの SKU別 `発注数` 合計 ÷ 受注データ期間の日数 |
| 在庫日数（DOS） | `有効在庫 ÷ 日次平均出庫` |
| 平均在庫日数（KPI） | `有効在庫合計 ÷ 日次出庫合計`（**加重平均**） |
| 残日数 | `賞味期限 − 今日` |
| 滞留日数 | `今日 − 最終出庫日` |

- 日次平均出庫の `発注数` には、サンプル行やギフトセット構成品の行（売上¥0）も含む。
  在庫から**物理的に出ていく量**を測るためで、意図どおり。
- 現データの出庫ペース算定期間は 2026-06-01〜2026-08-31（92日）。

### 設計判断と理由（変える前にユーザーへ確認すること）

| 判断 | 理由 |
|---|---|
| 残日数・滞留日数は**今日（閲覧時のブラウザ日付）**基準 | データの最新日基準だと、今日すでに期限切れのロットが期限内に見える。データ鮮度はヘッダーに別表示し、8日以上古ければ経過日数も併記 |
| 平均在庫日数は**加重平均** | 出庫の少ない商品は在庫日数が数千日になり、単純平均が引きずられる |
| 商品名ではなく **SKU** で突合 | 表記が違いすぎて名前では一致しない（§6） |
| 未突合は**空欄**（推測しない） | 仮の値は実績と誤読される |
| 在庫日数 3650日超は「10年超」と表示 | 桁が大きすぎて読めないため |

## 8. ステータス判定としきい値

SKU 単位で判定（`InventoryScripts.html` の `statusOf()`）。しきい値は `Code.gs` の `DEFAULT_CONFIG`。

| ステータス | 条件 | Config キー | 既定 |
|---|---|---|---|
| 単価未突合 | 購入価格が取れない | — | — |
| 出庫なし | 日次平均出庫が0 | — | — |
| 要補充 | 在庫日数 < 値 | `inventoryLowDays` | 14 |
| 適正 | 在庫日数 ≤ 値 | `inventoryHealthyDays` | 90 |
| 過剰 | 在庫日数 ≤ 値 | `inventoryExcessDays` | 365 |
| 大幅過剰 | 上記を超える | — | — |

その他：滞留 `inventoryStagnantDays`（90日超）、期限接近 `inventoryExpirySoonDays`（残90日以内）。
期限の帯は 期限切れ / 30日以内 / 90日以内 / 180日以内 / 181日以上 / 期限なし。

**注意：Config シートで上書きすると現状は文字列のまま入る（§11-2）。**

| セクション | Kicker | 内容 |

## 11. 既知の課題・未決事項

### 11-1. 実GAS環境で未検証（最優先）

`Code.gs` は構文チェックのみ。Spreadsheet・GAS 上での実行、`getDisplayValues()` による日付・数値の読み方、
権限・公開設定は一度も確認していない。デプロイ手順は `docs/cw-dashboard-b2b.md` §2 を参照し、
在庫ページには追加で以下が必要：

- シート `RAW_Inventory`（在庫CSVを UTF-8 で取り込む）と `RAW_B2B`
- GAS プロジェクトに `Inventory.html` と `InventoryScripts.html` を**同名で**追加

### 11-2. Config の在庫しきい値が数値化されない（不具合）

`Code.gs` の `readConfig_()` は `followOverdueDays` だけを `parseNumber_()` し、
`inventoryLowDays` などは `cfg[key] = val` で**文字列のまま**入れている。
比較演算の型変換で多くの場合は動くが、**値が空欄だと `''` → 0 扱いになり判定が崩れる**。

修正案：在庫しきい値の5キーも `parseNumber_()` を通し、空欄なら既定値を残す。
直す場合は `build_preview.py` 側（`INVENTORY_THRESHOLDS` は固定値）との整合も確認すること。
**ユーザーにはまだ修正の可否を確認していない。** 着手前に確認すること。

### 11-3. 単価未突合の9 SKU

受注側に SKU が無いため在庫金額・在庫日数が出ない（§6）。解決には次のいずれかが必要で、
**どちらにするかはユーザーの判断**：
- 受注システム側にその SKU と購入価格を登録する
- `Product_Master` 等に SKU→購入価格の対応表を用意し、`getInventoryData()` で補完する（未実装）

### 11-4. 賞味期限が一部ロットにしか無い

27/127 ロットのみ。期限管理はその範囲に限られる。全ロットに必要かはユーザー確認事項。

### 11-5. 出庫ペースの期間

受注データの期間（現在92日）全体の平均。季節性（お中元・お歳暮）は考慮していない。
直近N日で測るなどの変更は指標の意味が変わるので、ユーザー確認の上で行う。

### 11-6. 実データがリポジトリにコミットされている

`data/` の CSV は実データ（受注側は顧客名を含む）。Artifact は既定で非公開だが、
共有範囲を広げる操作はユーザーの指示なしに行わないこと。

## 12. 検証の方法

### プレビュー生成

  --inventory data/RAW_Inventory_sample.csv \
