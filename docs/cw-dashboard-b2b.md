# CW Dashboard｜業務用・飲食店 受注売上ダッシュボード

`CW_Dashboard_Design_Handoff_Prompt` を共通Master UIとして実装した、
Google Spreadsheet → GAS → HTML 構成の社内Dashboardページ。

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `apps/cw-dashboard/Code.gs` | GASバックエンド。シート読込・正規化・フィルター候補生成 |
| `apps/cw-dashboard/Index.html` | ページのシェル。Header / Nav / 各セクションのマークアップ |
| `apps/cw-dashboard/Styles.html` | 共通CSS変数とMaster UIのスタイル（全ページ共通） |
| `apps/cw-dashboard/Scripts.html` | データ取得・集計・描画・フィルター・並び替え |
| `apps/cw-dashboard/appsscript.json` | GASプロジェクト設定 |
| `apps/cw-dashboard/tools/build_preview.py` | GAS無しで開けるプレビューHTMLの生成 |
| `apps/cw-dashboard/tools/build_product_master.py` | `Product_Master` のひな形生成（原価入力用） |
| `apps/cw-dashboard/preview/b2b.html` | 上記の生成物（自動生成・直接編集しない） |

`Styles.html` はページ間で共有する。**在庫・EC・SNS等を追加するときも、このファイルを
書き換えるのではなく、そのまま読み込むこと**（引き継ぎ書 §22）。

## 1. Spreadsheet 構成

### 1.1 `RAW_B2B`（必須）

受注明細のローデータ。1行 = 1明細（1受注に複数商品行）。
1行目が見出しで、以下の列名をそのまま使う（受注管理システムのCSVエクスポートと同じ）。

| 列名 | 用途 | 例 |
|---|---|---|
| `ステータス` | 集計対象の判定 | `確定済み` / `完了` / `下書き` / `合計` |
| `日付` | 受注日 | `2026/06/01` |
| `出荷予定日` | 出荷Lead算出・日付基準の切替 | `2026/06/03` |
| `受注書番号` | 受注件数のユニークキー | `SO-00016` |
| `リード種別` | 営業経路 | `社員紹介` / 空欄 |
| `新規/リピート` | リピート率 | `新規` / `リピート` |
| `顧客種別` | 業務店スコープの判定 | `飲食店` / `卸売` / `EC（自社サイト）` |
| `EC（他社サイト）の詳細` | 補足 | |
| `顧客名` | 店舗・取引先 | `アルコールフォレスト` |
| `営業担当者` | 担当者別分析 | `shintaro.iwai` |
| `受注書ID` | （未使用・保持のみ） | |
| `調整` / `配送料` / `合計` | 受注ヘッダ金額 | `¥500` |
| `請求日` | 日付基準の切替 | |
| `商品名` | 商品・カテゴリ判定 | `【ビール】Barrel Wonder（370ml）` |
| `区分` | 販売 / サンプル等。列展開の軸 | `販売` / `サンプル` / 空欄 |
| `販売価格` | 単価 | `¥4,900` |
| `発注数` | 数量 | `30` |
| `割引（%）` / `割引額` | 補足 | |
| `総額` / `合計（FCY）` | 補足 | |
| `小計` | **商品売上の集計元（税抜）** | `¥4,900` |
| `税込みの総額` | 補足 | |

金額は `¥1,234` 形式でも数値でも読める（`parseNumber_()` が両対応）。
日付は `2026/06/01` 形式でもDate型でも読める。

### 1.2 `Product_Master`（任意）

無い場合は商品名の `【…】` 接頭辞から自動判定する。
表記ゆれを厳密に管理したくなった時点で作成すればよい。

| 列名 | 内容 |
|---|---|
| `商品名` | RAW_B2B に現れる生の商品名 |
| `正規化商品名` | 表示・集計に使う正式名 |
| `カテゴリ` | `ビール` / `ウイスキー` / `リキュール` / `化粧箱` / `同梱物` / `ギフト資材` |
| `品目区分` | `完成品` / `資材` |
| `標準販売価格` | 参考表示用（集計には使わない） |
| `原価` | **粗利の算出元**。1商品＝1値の標準原価。空欄と`0`は区別され、空欄なら「原価未設定」と表示 |
| `原価注記` | 原価の出所を1行で書くと、画面上部に帯で表示される（サンプル原価の誤読防止） |

ひな形は次のコマンドで生成できる。

```bash
# 原価列が空のテンプレート（これに実原価を入力する）
python3 apps/cw-dashboard/tools/build_product_master.py \
  --csv data/RAW_B2B_sample.csv --out data/Product_Master_template.csv
```

突き合わせは `normalizeKey_()` で行うため、空白・全半角括弧・`〈〉`・
`Whisly`/`Whisky` の違いは吸収される。

### 1.3 `Config`（任意）

`キー` / `値` の2列。設定しない項目は既定値が使われる。

| キー | 既定値 | 内容 |
|---|---|---|
| `b2bCustomerTypes` | `飲食店,卸売,量販店・百貨店,酒販小売` | 業務店営業ページの対象顧客種別。空にすると全件 |
| `includeStatuses` | `確定済み,完了` | 集計対象のステータス |
| `excludeStatuses` | `合計` | 除外するステータス（合計行など） |

## 2. デプロイ手順

1. 対象のSpreadsheetを開き、**拡張機能 → Apps Script**。
2. 以下のファイルを同名で作成し、内容を貼り付ける。
   - `Code.gs`
   - `Index.html`（HTMLファイルとして作成）
   - `Styles.html`
   - `Scripts.html`
3. プロジェクトの設定で「`appsscript.json` マニフェストファイルをエディタで表示」を
   オンにし、`appsscript.json` の内容を反映する。
4. **デプロイ → 新しいデプロイ → 種類：ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**組織内の全員**（社内限定）
5. 発行されたURLを開く。`?page=b2b` が既定ページ。

Spreadsheetを更新したあとは、Dashboardを再読み込みすれば最新データが反映される
（初期版はページ読み込み時取得。定期更新は必要になってから追加する）。

## 3. プレビュー版（GAS無しで確認する）

デザインレビューやデータ検証を、GASにデプロイせずローカルで行うための生成物。

```bash
python3 apps/cw-dashboard/tools/build_preview.py \
  --csv data/RAW_B2B_sample.csv \
  --master data/Product_Master_sample.csv \
  --out apps/cw-dashboard/preview/b2b.html
```

`--master` は任意。省略すると原価が読まれず、粗利は「原価未設定」と表示される。

> `data/Product_Master_sample.csv` の原価は**サンプル値**（完成品＝標準販売価格×40%、
> 資材＝カテゴリ別の定額）で、実原価ではない。`原価注記` 列に書いた文言が画面上部の
> 帯に出るので、実原価に差し替えるときはこの列も空にすること。

`Index.html` / `Styles.html` / `Scripts.html` は本番と同一のものを使い、
`getDashboardData()` の返り値だけを `window.__CW_PREVIEW_DATA__` として注入する。
`Scripts.html` はこの変数があればGASを呼ばずにそちらを使う。

> `build_preview.py` の正規化処理は `Code.gs` の移植（プレビュー専用ミラー）。
> **仕様の正は `Code.gs`**。片方を直したらもう片方も合わせること。

## 5. 指標の定義

| 指標 | 定義 |
|---|---|
| 商品売上 | 明細 `小計` の合計（税抜）。配送料・調整額は含まない |
| 販売粗利 | **売上が立っている明細行**の `小計 − 原価`。原価 = `発注数 × Product_Master.原価` |
| 粗利率 | 販売粗利 ÷ 商品売上 |
| 無償提供原価 | **売上¥0の明細行**の原価合計。販売粗利には含めない |
| 直近増減 | 最終月と直前月の売上差。最終月が月途中なら前月も同じ日数に揃えて比較 |
| 受注件数 | `受注書番号` のユニーク数 |
| 取引店舗数 | `顧客名` のユニーク数 |
| 発注数量 | `発注数` の合計。販売・サンプル・イベント・協賛を含む |
| リピート受注率 | `新規/リピート` = `リピート` の受注 ÷ 全受注 |
| 平均出荷Lead | 受注日 → 出荷予定日の日数平均（負値は除外） |
| 平均店舗回転 | 受注件数 ÷ 店舗数 ÷ 対象月数 |
| 月平均回転 | 店舗の受注回数 ÷ 対象月数 |
| 平均発注間隔 | **受注日をユニーク化**した上での隣接日数の平均 |
| 前期 | 選択期間と同じ日数だけ手前にずらした期間 |

### 販売と無償を「区分」で分けない理由

引き継ぎ書の区分（販売 / サンプル / イベント / 協賛 / 未入力）で分けると、
実データでは次の売上が粗利計算から漏れる。

| 区分 | 売上あり行 | 売上合計 | 売上¥0行 |
|---|---|---|---|
| 販売 | 292 | ¥5,129,602 | 11 |
| サンプル | 3 | ¥45,708 | 159 |
| 未入力 | 1 | ¥27,440 | 63 |
| 協賛 | 2 | ¥15,600 | 12 |
| イベント | 0 | ¥0 | 7 |

区分「サンプル」「協賛」「未入力」にも売上のある行が実在し、区分で分けると
¥88,748（売上の1.7%）が粗利の対象外になる。このため
**`小計 > 0` かどうか**で販売／無償を分けている。区分は列展開・フィルターの軸として
そのまま使う。

### トレンドの積み上げ内訳と「他 N件」

TREND の棒は、区分・商品・商品カテゴリ・顧客種別・店舗のいずれかで積み上げられる。
`月次 × 商品` にすると、MONTHLY × PRODUCT テーブルと同じ内容をグラフで見られる
（棒の合計は同テーブルの合計行と一致する）。

配色はモノトーン＋ゴールドの濃淡ランプ8色に限っている（§12）。商品176件・店舗176件を
そのまま積むと見分けがつかないため、既定では上位6件を表示し、残りを1本の帯にまとめる。
表示件数は上位6 / 上位10 / すべてから選べ、**まとめても棒の合計は変わらない**。
全件の内訳は下の MONTHLY × PRODUCT テーブルで確認できる。

まとめ帯のラベルは「その他」ではなく **「他 N件」**。実データに `その他` という
カテゴリが存在し、「その他」を使うと凡例に同名の帯が2つ並んでしまうため。
まとめる対象が1件しかないときは帯の数が減らないので、まとめずにそのまま表示する。

### 原価に含める範囲

- 商品原価（酒類本体）
- 資材原価（化粧箱・同梱物・ギフト資材）— 受注明細に行として入っているため、
  マスタに原価を入れるだけで自動的に拾われる
- 配送料は**含めない**（受注ヘッダの値で、明細行への按分ルールが未定のため）

### 原価未設定の扱い

`Product_Master.原価` が空欄の商品は原価0として集計され、粗利が実際より大きく出る。
画面上部の帯に「原価設定済み N / M 商品」を常時表示し、未設定があることを明示する。
1件も設定が無い場合は粗利KPIを「原価未設定」と表示し、数値を出さない。

### 算出していないもの

- **店舗の在庫回転率**：店頭POS・店頭在庫データが無いため算出しない。
  代理指標として「月平均受注回数」「平均発注間隔」を使用する。

### 平均発注間隔を受注日ユニークで測る理由

同じ店舗に同日付で複数の受注書が起票されるケースがあり、そのまま受注書単位で
間隔を測ると平均が 0 日になる。すると「最終受注からの経過日数 − 平均発注間隔」が
経過日数そのものになり、フォロー候補の上位を実態のない店舗が占めてしまう。
受注日をユニーク化すると、同日複数受注は 1 回の発注機会として扱われ、
間隔が測れない店舗（受注日が1日しかない）はフォロー候補から自然に外れる。

## 6. 表記ゆれの補正

実データで確認した以下を `Code.gs` / `Product_Master` で吸収している。

| 種類 | 例 | 補正 |
|---|---|---|
| カテゴリの日英ゆれ | `【ビール】` / `【BEER】`、`【ウイスキー】` / `【WHISKEY】` / `【Whisky】` | カテゴリを1つに寄せる |
| 綴り誤り | `Rice Whisly Wonder` → `Rice Whisky Wonder` | 商品名を置換 |
| 全角スペース・連続スペース | `Yuzu White Wonder　（310ml）` | 半角1つに正規化 |
| 顧客種別の前後空白 | ` EC（他社サイト）` | trim |
| 接頭辞 | `●父の日仕様●` / `社販` | カテゴリ判定時に無視 |
| 語順ゆれ | `Gift Set （370ml）〈BW / EW 各1本〉` / `〈BW / EW 各1本〉Gift Set （370ml）` | `Product_Master` の `正規化商品名` で統合（マスタ未整備時は別商品のまま） |

`〈…〉` は**除去しない**。`Non Ale Wonder 0.00%（370ml）〈Ginger〉` と `〈Yuzu〉` は
別商品であり、除去すると集計上まとまってしまうため。

## 7. 情報量に関する方針

引き継ぎ書 §23 の「情報量を削減して見た目だけ簡潔にすること」を避けるため、
以下は**件数を打ち切らずに全件描画**し、パネル内スクロールで整理している。

- 比較分析のランキング（全 N 件）
- 店舗別 再発注回転（全店舗）
- フォロー候補（全件）
- 月別 商品別 売上・数量比較（全行）
- 店舗別 注文商品・本数（全行）

各パネル下部に「全 N 件を表示」を出し、打ち切りでないことを明示する。
テーブルには合計行（`tfoot`）を固定表示する。

## 8. 今後の拡張

`Code.gs` の `getDashboardData({page})` に分岐を足し、
`Index.html` のナビゲーションを有効化していく。

```text
CRAFT WONDER DASHBOARD
├ Overview
├ Sales ─ 業務店営業（本ページ） / EC売上
├ SCM   ─ 在庫 / 出荷
├ Marketing ─ CRM / SNS / 広告
└ Report ─ Monthly
```

在庫ページを追加する場合、`Styles.html` はそのまま共有し、
`getInventoryData()` を `Code.gs` に追加、`RAW_Inventory` シートを新設する。
在庫のローデータ形式は `data/RAW_Inventory_sample.csv` を参照（WMS在庫明細の
エクスポート。`在庫数` / `引当数` / `未引当数` / `最終入庫日` / `最終出庫日` 等を含む）。
