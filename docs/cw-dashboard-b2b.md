# CW Dashboard｜業務用・飲食店 受注売上ダッシュボード

`CW_Dashboard_Design_Handoff_Prompt` を共通Master UIとして実装した、
Google Spreadsheet → GAS → HTML 構成の社内Dashboardページ。

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `apps/cw-dashboard/Code.gs` | GASバックエンド。シート読込・正規化・フィルター候補生成 |
| `apps/cw-dashboard/Index.html` | ページのシェル。Header / Nav / 各セクションのマークアップ |
| `apps/cw-dashboard/Styles.html` | 共通CSS変数とMaster UIのスタイル（全ページ共通） |
| `apps/cw-dashboard/Scripts.html` | データ取得・集計・描画・フィルター・並び替え |
| `apps/cw-dashboard/appsscript.json` | GASプロジェクト設定 |
| `apps/cw-dashboard/tools/build_preview.py` | GAS無しで開けるプレビューHTMLの生成 |
| `apps/cw-dashboard/tools/build_product_master.py` | `Product_Master` のひな形生成（原価入力用） |
| `apps/cw-dashboard/preview/b2b.html` | 上記の生成物（自動生成・直接編集しない） |

### 1.2 `Product_Master`（任意）

無い場合は商品名の `【…】` 接頭辞から自動判定する。
表記ゆれを厳密に管理したくなった時点で作成すればよい。

| 列名 | 内容 |
|---|---|
| `商品名` | RAW_B2B に現れる生の商品名 |
| `正規化商品名` | 表示・集計に使う正式名 |
| `カテゴリ` | `ビール` / `ウイスキー` / `リキュール` / `化粧箱` / `同梱物` / `ギフト資材` |
| `品目区分` | `完成品` / `資材` |

## 2. デプロイ手順

1. 対象のSpreadsheetを開き、**拡張機能 → Apps Script**。
2. 以下のファイルを同名で作成し、内容を貼り付ける。
   - `Code.gs`
   - `Index.html`（HTMLファイルとして作成）
   - `Styles.html`
   - `Scripts.html`
3. プロジェクトの設定で「`appsscript.json` マニフェストファイルをエディタで表示」を
   オンにし、`appsscript.json` の内容を反映する。
4. **デプロイ → 新しいデプロイ → 種類：ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**組織内の全員**（社内限定）
5. 発行されたURLを開く。`?page=b2b` が既定ページ。

Spreadsheetを更新したあとは、Dashboardを再読み込みすれば最新データが反映される
（初期版はページ読み込み時取得。定期更新は必要になってから追加する）。

## 5. 指標の定義

| 指標 | 定義 |
|---|---|
| 商品売上 | 明細 `小計` の合計（税抜）。配送料・調整額は含まない |
| 原価 | `購入価格 × 発注数`。配送料・調整額は含まない |
| 販売粗利 | **売上のある受注**の `売上 − 原価` |
| 粗利率 | 販売粗利 ÷ 商品売上 |
| 無償提供原価 | **売上¥0の受注**の原価合計 |
| 純粗利 | `販売粗利 − 無償提供原価`（全明細の 売上 − 原価 と一致） |
| 純粗利率 | 純粗利 ÷ 商品売上 |
| 直近増減 | 最終月と直前月の売上差。最終月が月途中なら前月も同じ日数に揃えて比較 |
| 受注件数 | `受注書番号` のユニーク数 |
| 取引店舗数 | `顧客名` のユニーク数 |
| 発注数量 | `発注数` の合計。販売・サンプル・イベント・協賛を含む |
| リピート受注率 | `新規/リピート` = `リピート` の受注 ÷ 全受注 |
| 平均出荷Lead | 受注日 → 出荷予定日の日数平均（負値は除外） |
| 平均店舗回転 | 受注件数 ÷ 店舗数 ÷ 対象月数 |
| 月平均回転 | 店舗の受注回数 ÷ 対象月数 |
| 平均発注間隔 | **受注日をユニーク化**した上での隣接日数の平均 |
| 前期 | 選択期間と同じ日数だけ手前にずらした期間 |

### 粗利の算出

粗利 = `(販売価格 − 購入価格) × 発注数`。`小計 = 販売価格 × 発注数` が全行で成立して
いるため、`小計 − 購入価格 × 発注数` と同じ値になる。

### 販売と無償を「受注単位」で分ける理由

**ギフトセットは売上だけの行で、その原価は同じ受注内の構成品行（売上¥0）に
分かれている。** 例（受注 SO-00017）:

| 明細 | 売上 | 原価 |
|---|---|---|
| 【BEER】Gift Set（370ml）〈BW / EW 各1本〉 | ¥4,900 | ¥0 |
| 【ビール】Barrel Wonder（370ml） | ¥0 | ¥905 |
| 【ビール】Eisbock Wonder（370ml） | ¥0 | ¥1,300 |
| 【化粧箱】ビールギフトボックス（370ml）〈2本セット〉 | ¥0 | ¥565 |
| 【ギフト資材】ショッパー（W210×H300mm） | ¥0 | ¥165 |
| 【同梱物】BW/EW リーフレット（A6）〈2つ折り〉 | ¥0 | ¥72 |
| **受注合計** | **¥4,900** | **¥3,007** |

明細行単位で「売上>0か」で分けると、構成品5行がサンプル同様の無償提供扱いになり、
販売粗利率が **45.7% → 55.7%** と約10ポイント過大に出る。
このため**受注書番号ごとに売上合計>0かどうか**で販売／無償を分けている。

区分（販売 / サンプル / イベント / 協賛）では分けない。区分「サンプル」「協賛」
「未入力」にも売上のある行が実在し、区分で分けると売上の一部が粗利の対象外になる。
区分は列展開・フィルターの軸としてそのまま使う。

### 商品別の粗利率が歪む範囲

上のセット構造のため、**商品・カテゴリ・区分を軸にした粗利率は正確でない**。

- ギフトセット商品 → 原価¥0なので粗利率100%
- その構成品 → 売上¥0なので粗利がマイナス

合計は正しく、**店舗別・顧客種別別・リード種別別・営業担当別は受注単位で閉じるため
正確**。画面下部の注記にもこの範囲を明記している。

将来 `Product_Master` に BOM（構成品・員数）を持たせれば、セットの原価を構成品から
積み上げて商品別粗利率も正確にできる。

### トレンドのデータラベル

各棒の上に合計値を出す。表記は軸ラベルと同じ丸め（金額は `¥1.9M` / `¥473k`、
数量は実数）で、正確な値は棒のツールチップと下のテーブルで確認する。

- ラベルは**実際に積み上がった高さ**に対して付ける。合計値をそのまま使うと、
  描画されない帯（0以下）があるときに棒の高さとラベルがずれる。
- 日次のように棒が密なときは、ラベル幅と棒間隔から間引き数を決めて重なりを防ぐ
  （73日分でも18件まで間引かれる）。
- 受注件数の折れ線より**後**に描き、白いハロー（`paint-order="stroke"`）を敷く。
  先に描くと線がラベルの上を通って読めなくなる。

### トレンドの積み上げ内訳と「他 N件」

TREND の棒は、区分・商品・商品カテゴリ・顧客種別・店舗のいずれかで積み上げられる。
`月次 × 商品` にすると、MONTHLY × PRODUCT テーブルと同じ内容をグラフで見られる
（棒の合計は同テーブルの合計行と一致する）。

配色はモノトーン＋ゴールドの濃淡ランプ8色に限っている（§12）。商品176件・店舗176件を
そのまま積むと見分けがつかないため、既定では上位6件を表示し、残りを1本の帯にまとめる。
表示件数は上位6 / 上位10 / すべてから選べ、**まとめても棒の合計は変わらない**。
全件の内訳は下の MONTHLY × PRODUCT テーブルで確認できる。

まとめ帯のラベルは「その他」ではなく **「他 N件」**。実データに `その他` という
カテゴリが存在し、「その他」を使うと凡例に同名の帯が2つ並んでしまうため。
まとめる対象が1件しかないときは帯の数が減らないので、まとめずにそのまま表示する。

### 原価に含める範囲

- 商品原価（酒類本体）— `購入価格`
- 資材原価（化粧箱・同梱物・ギフト資材）— 受注明細に行として入っているため自動的に拾われる。
  資材は販売価格が¥0なので**単体では粗利がマイナス**になり、セット販売の原価として
  同じ受注内で回収される
- 配送料は**含めない**（受注ヘッダの値で、明細行への按分ルールが未定のため）

### 購入価格の欠落・¥0 の扱い

画面上部の帯に、絞り込み後のスコープを基準として次を常時表示する。

- **購入価格あり N / M 商品** — 空の商品は原価0として集計され、粗利が過大に出る
- **購入価格¥0のまま売上がある N 商品** — ギフトセットなら構成品行に原価があるので
  合算すれば正しい。それ以外は購入価格マスタの未整備が疑われる

同じ内容を `warnings` にも出すと全データ基準の件数になり帯と食い違うため、
この2件は帯だけに出している。1件も購入価格が読めない場合は粗利KPIを
「原価未設定」と表示し、数値を出さない。

### 算出していないもの

- **店舗の在庫回転率**：店頭POS・店頭在庫データが無いため算出しない。
  代理指標として「月平均受注回数」「平均発注間隔」を使用する。

### 平均発注間隔を受注日ユニークで測る理由

同じ店舗に同日付で複数の受注書が起票されるケースがあり、そのまま受注書単位で
間隔を測ると平均が 0 日になる。すると「最終受注からの経過日数 − 平均発注間隔」が
経過日数そのものになり、フォロー候補の上位を実態のない店舗が占めてしまう。
受注日をユニーク化すると、同日複数受注は 1 回の発注機会として扱われ、
間隔が測れない店舗（受注日が1日しかない）はフォロー候補から自然に外れる。

## 6. 表記ゆれの補正

実データで確認した以下を `Code.gs` / `Product_Master` で吸収している。

| 種類 | 例 | 補正 |
|---|---|---|
| カテゴリの日英ゆれ | `【ビール】` / `【BEER】`、`【ウイスキー】` / `【WHISKEY】` / `【Whisky】` | カテゴリを1つに寄せる |
| 綴り誤り | `Rice Whisly Wonder` → `Rice Whisky Wonder` | 商品名を置換 |
| 全角スペース・連続スペース | `Yuzu White Wonder　（310ml）` | 半角1つに正規化 |
| 顧客種別の前後空白 | ` EC（他社サイト）` | trim |
| 接頭辞 | `●父の日仕様●` / `社販` | カテゴリ判定時に無視 |
| 語順ゆれ | `Gift Set （370ml）〈BW / EW 各1本〉` / `〈BW / EW 各1本〉Gift Set （370ml）` | `Product_Master` の `正規化商品名` で統合（マスタ未整備時は別商品のまま） |

`〈…〉` は**除去しない**。`Non Ale Wonder 0.00%（370ml）〈Ginger〉` と `〈Yuzu〉` は
別商品であり、除去すると集計上まとまってしまうため。

## 7. 情報量に関する方針

引き継ぎ書 §23 の「情報量を削減して見た目だけ簡潔にすること」を避けるため、
以下は**件数を打ち切らずに全件描画**し、パネル内スクロールで整理している。

- 比較分析のランキング（全 N 件）
- 店舗別 再発注回転（全店舗）
- フォロー候補（全件）
- 月別 商品別 売上・数量比較（全行）
- 店舗別 注文商品・本数（全行）

各パネル下部に「全 N 件を表示」を出し、打ち切りでないことを明示する。
テーブルには合計行（`tfoot`）を固定表示する。
