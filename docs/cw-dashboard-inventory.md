# CW Dashboard｜在庫ダッシュボード

`CW_Dashboard_Design_Handoff_Prompt` を共通Master UIとして実装したSCMページ。
営業ページ（`docs/cw-dashboard-b2b.md`）と `Styles.html` を共有する（§22）。

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `apps/cw-dashboard/Code.gs` | `getInventoryData()` で在庫を組み立てる（営業ページと共通） |
| `apps/cw-dashboard/Inventory.html` | ページのシェル |
| `apps/cw-dashboard/InventoryScripts.html` | 集計・描画・フィルター |
| `apps/cw-dashboard/Styles.html` | **営業ページと共有**。書き換えない |
| `apps/cw-dashboard/preview/inventory.html` | 自動生成物（直接編集しない） |

URLは `?page=inventory`。

## 1. `RAW_Inventory`（必須）

WMSの在庫明細エクスポート。**1行 = 1ロット**。

| 列名 | 用途 |
|---|---|
| `商品コード` | **受注データとの突合キー**（JAN）。`SKU（在庫保管単位）` と突き合わせる |
| `商品名` | 倉庫側の表記。表示には受注側の名前を優先する |
| `拠点名` / `在庫区分名` / `仕入先名` | フィルター軸 |
| `在庫数` | 総在庫 |
| `引当数` | 出荷待ちで確保済み |
| `未引当数` | **有効在庫**。在庫日数の分子 |
| `入荷実績数` / `出荷実績数` | 保持のみ |
| `ロットNo` / `入荷日` / `賞味期限` | ロット明細・期限管理 |
| `最終入庫日` | データ鮮度の判定に使う |
| `最終出庫日` | 滞留日数の起点 |

`カテゴリー名` は実データで全行空欄のため使わず、商品カテゴリは商品名の
`【…】` 表記から判定する（営業ページと同じ `guessProduct_()`）。

---

## 2. 受注データとの突き合わせ

単価と出庫ペースは在庫データに無いため、`RAW_B2B` から取得する。

**突合キーは `RAW_B2B.SKU（在庫保管単位）` ＝ `RAW_Inventory.商品コード`。**

商品名は突合に使えない。同じ商品でも表記が大きく異なるため。

| | 表記 |
|---|---|
| 在庫側 | `★【ビール】Barrel Wonder　Amber Ale 001【370ml】` |
| 受注側 | `【ビール】Barrel Wonder（370ml）` |

実データでの突合結果は **31 / 40 SKU**。残り9件は受注側にSKUが存在しない
資材・ノベルティ（`BEER-G-260501` のような自社コード）で、
**在庫数量は集計するが在庫金額と在庫日数は算出しない**。画面上部の帯で常時明示する。

## 3. 指標の定義

| 指標 | 定義 |
|---|---|
| 在庫金額 | `在庫数 × 購入価格`（原価ベース）。単価が突き合った商品のみ |
| 有効在庫 | `未引当数`。引当済みは出荷待ちで確保されている分 |
| 日次平均出庫 | 受注データの `発注数` 合計 ÷ 受注データの期間日数 |
| 在庫日数（DOS） | `有効在庫 ÷ 日次平均出庫` |
| 平均在庫日数 | `有効在庫合計 ÷ 日次出庫合計`（**加重平均**） |
| 残日数 | `賞味期限 − 今日` |
| 滞留日数 | `今日 − 最終出庫日` |

### 平均在庫日数を加重平均にする理由

SKUごとの在庫日数は、出庫が極端に少ない商品で数千日に達する。単純平均だと
そうした少数のSKUに引きずられるため、`有効在庫合計 ÷ 日次出庫合計` で算出する。

### 基準日に「今日」を使う理由

賞味期限の残日数と滞留日数は**今日**を基準に計算する。

在庫データの最新日（最終入庫日の最大値）を基準にすると、今日すでに期限切れの
ロットが期限内として表示され、現場の判断を誤らせる。実データでも、最終入庫日
基準では期限切れ0ロット、今日基準では5ロットと結果が変わる。

代わりに**データの鮮度**をヘッダーに出し、8日以上古い場合は経過日数も併記する。

## 4. 在庫ステータス

`Config` で変更できる（既定値）。

| ステータス | 条件 | 既定しきい値 |
|---|---|---|
| 要補充 | 在庫日数 < `inventoryLowDays` | 14日 |
| 適正 | 在庫日数 ≤ `inventoryHealthyDays` | 90日 |
| 過剰 | 在庫日数 ≤ `inventoryExcessDays` | 365日 |
| 大幅過剰 | 上記を超える | — |
| 出庫なし | 受注データに出庫が無い | — |
| 単価未突合 | SKUが受注側に無い | — |

滞留の判定は `inventoryStagnantDays`（90日）、期限接近は
`inventoryExpirySoonDays`（90日）。

## 5. ページ構成

| セクション | Kicker | 内容 |
|---|---|---|
| Header | — | タイトル / 更新日時 / ロット・SKU数 / データ鮮度 / 出庫ペース算定期間 |
| Filter Area | — | 3列グリッド。**リセットは右下固定** |
| KPI Cards | — | 14指標（在庫金額・数量・有効在庫・引当・期限・補充・過剰・滞留ほか） |
| Value Mix / Coverage / Expiry | `VALUE MIX` `COVERAGE` `EXPIRY` | カテゴリ別金額ドーナツ／在庫日数分布／期限残日数 |
| Operating Signals | `OPERATING SIGNAL` | 期限切れ・期限接近・要補充・大幅過剰・出庫なし・未突合 |
| Inventory by Product | `INVENTORY BY PRODUCT` | **1商品 = 1行**。全件表示・合計行固定 |
| Product × Lot | `PRODUCT × LOT` | **1商品 × 1ロット = 1行**。全件表示・合計行固定 |

フィルターは品目区分 / カテゴリ / 商品 / 在庫ステータス / 賞味期限 / 仕入先 /
拠点 の7種と「在庫0を含める」。ステータスと期限は算出値なので候補もデータから作る。

## 6. プレビュー生成

```bash
python3 apps/cw-dashboard/tools/build_preview.py --page inventory \
  --inventory data/RAW_Inventory_sample.csv \
  --csv data/RAW_B2B_sample.csv \
  --out apps/cw-dashboard/preview/inventory.html
```

`--csv`（受注データ）は単価と出庫ペースの取得に必須。
